# Syncpad Landing Page

This reference applies to public-facing Syncpad marketing surfaces.

The landing page has a different job from the product application.

Product UI optimizes for:

- efficiency
- scanning
- task completion

Landing UI optimizes for:

- comprehension
- product positioning
- trust
- product desire
- conversion

The landing page should still feel like the same Syncpad brand.

---

# Primary Goal

A visitor should understand within the first viewport:

1. What Syncpad is.
2. Why it is useful.
3. What the product feels like.
4. What they should do next.

Do not require scrolling to understand the core product.

---

# First Viewport Goal

The first viewport should communicate:

Syncpad is a collaborative document workspace for writing and working
together in real time.

The visual hierarchy should roughly be:

Navigation
→ product message
→ supporting explanation
→ primary CTA
→ secondary CTA if needed
→ product visual

The product visual should reinforce the message rather than merely
decorate the page.

---

# Hero Copy

Prefer a short, confident headline.

Avoid:

- long feature lists
- vague AI/SaaS language
- exaggerated claims
- generic words such as "revolutionize"
- several sentences inside the headline

The headline should describe the outcome or core product idea.

Supporting copy can explain:

- collaborative writing
- live teamwork
- comments
- document organization
- simplicity

Keep hero copy compact.

---

# Hero Visual

Show the real Syncpad product.

Prefer:

- editor UI
- collaborative presence
- comments
- document surface
- recognizable real product interaction

over:

- abstract 3D objects
- fake dashboard metrics
- stock illustrations
- generic browser mockups with meaningless content

The product preview may be cropped, layered, or slightly stylized.

Do not distort it so much that it stops looking like a real product.

---

# Composition

The first viewport should feel intentional and spacious without becoming
empty.

Prefer a strong composition such as:

Option A:
centered copy
→ CTA
→ large product preview

Option B:
copy on left
→ product visual on right

Choose based on what best communicates the product.

Do not default to split hero solely because it is common.

---

# Navigation

Keep navigation minimal.

Likely elements:

- Syncpad logo
- Product / Features if useful
- Templates if useful
- Sign in
- Primary CTA

Do not add navigation items for pages that do not meaningfully exist.

The primary CTA should remain visually dominant.

---

# Product Personality

The landing page should feel:

- simple
- friendly
- editorial
- crafted
- modern
- trustworthy
- slightly playful
- human

It should not feel:

- corporate enterprise
- generic SaaS
- crypto
- overly futuristic
- excessively animated
- sterile

---

# Illustration

Illustration may be used as a secondary brand layer.

Use hand-drawn or lightweight visual details around product content.

Good:

- arrow pointing to collaboration detail
- small annotation around document UI
- simple doodle supporting a message
- subtle hand-drawn accent

Bad:

- illustration replacing the product itself
- several decorative elements fighting for attention
- large mascot-style scenes without product relevance

---

# Background Treatment

Prefer a clean neutral base.

Subtle patterns may be used to give large empty areas character.

Patterns should remain low contrast.

They should disappear perceptually before:

- headline
- CTA
- product visual

If the background becomes one of the first things the user notices, it
is too strong.

---

# Motion

Motion should make the hero feel intentional.

Suitable:

- short text entrance
- product UI reveal
- subtle stagger
- hover interactions
- small illustrated movement

Avoid:

- continuous floating
- excessive parallax
- large scroll choreography
- distracting looping animation

The hero should still look excellent when completely static.

---

# CTA Hierarchy

Normally use one strong primary CTA.

Examples:

- Start writing
- Get started
- Try Syncpad

A secondary action may exist for:

- viewing demo
- seeing product
- signing in

Do not show multiple equally dominant CTAs.

---

# First Viewport Constraint

For the initial task, design ONLY the first viewport.

Do not design the entire landing page.

This phase should establish:

- navigation
- hero typography
- product positioning
- CTA hierarchy
- product visual treatment
- background language
- illustration language
- motion character

Do not build sections below the hero until this direction has been
reviewed.

The first viewport acts as the visual foundation for the rest of the
landing page.
